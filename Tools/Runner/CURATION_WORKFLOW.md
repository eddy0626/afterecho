# 잔향 채보 선별·검수 팀 안내

중앙 동심원과 한 손 입력에 맞는 노트를 고르고, 원곡과 비교한 사람의 검수 기록을 남기는 작업 순서입니다. 기존 BeatLearning 후보를 게임 규칙에 맞게 **선별하는 도구**이며, 새로 학습한 모델이 아닙니다. 이번 작업은 HP·피해량·질주 조건·이동 속도를 바꾸지 않습니다.

기술 검사 통과는 노트 간격·연속 패턴·동시에 보이는 원 등의 제약을 만족한다는 뜻입니다. 음악적으로 자연스럽거나 한 손으로 적절하다는 승인은 별도입니다. 실제 노트 수와 대기 항목은 각 실행의 보고서에서 확인하세요.

## 1. Unity에서 검수 시작

1. 개편 러닝 씬을 열고 **Afterecho > Chart Lab**을 선택합니다. 모드는 `runner`, 난이도는 `easy`·`normal`·`hard` 중 하나를 고릅니다.
2. 기본 채보는 `기본 채보 다시 읽기`, 선별 결과나 이전 편집본은 `JSON 불러오기`로 엽니다. 검수할 파일의 경로와 난이도를 확인합니다.
3. `현재 채보 기술 검사`를 실행합니다. `기본 채보 회귀검사`는 Resources에 들어 있는 기본 채보를 검사하므로, 현재 불러온 편집본의 검사와 구분합니다. 회귀검사 상세 결과는 화면에 표시된 보고서 경로에 저장됩니다.
4. `검수 필터`를 `pending`으로, `큰 이동만 (|원시→현재| ≥ 실제 판정창)`을 켜서 시각 차이가 큰 노트를 먼저 확인합니다. 이후 필터를 풀고 구절 경계·쉼·빠른 패턴까지 검수합니다. 큰 이동은 확인 우선순위이며, 자동으로 틀린 노트라는 뜻은 아닙니다.

Chart Lab을 열거나 다시 선택하면 진행 중인 게임은 일시정지합니다. 검수자·이유를 입력하는 동안 게임 헛입력으로 처리되지 않게 하기 위한 동작입니다. 게임을 이어 하려면 **Game 뷰에서 재개**하세요. 기존 4박 준비 후 이어지며, A/B 청음 종료가 게임을 자동 재개하지는 않습니다.

## 2. 시각과 상태 읽기

| 표시·데이터 | 의미 |
|---|---|
| 원시 AI / `originalTime` | 공개 모델이 처음 제안한 시각. 정답으로 간주하지 않습니다. |
| 이전 보정 / `parentTime` | 현재 선별본보다 앞선 보정 시각. 과거 수정과 비교할 때 사용합니다. |
| 현재 / `time` | 현재 문서에서 실제 게임에 적용하는 시각. 단위는 초입니다. |
| 이동 ms | 현재 시각에서 원시 AI 시각을 뺀 값. 음수는 앞당김, 양수는 늦춤입니다. |
| 실제 ±판정창 | 해당 노트에 적용하는 입력 허용 범위. 큰 이동 필터는 이 값과 비교합니다. |
| `sourceRetimed` | 현재 시각이 원시 시각에서 바뀌었는지 나타냅니다. 원시 시각이 없는 수동 노트와 구분합니다. |
| `pending` | 청음·입력 검수가 남았거나, 수정으로 이전 승인이 무효화된 상태입니다. |
| `approved` | 현재 시각을 사람이 확인했고 유효한 검수 기록이 연결된 상태입니다. |
| `rejected` | 사람이 현재 후보를 채택하지 않기로 기록한 상태입니다. |

`reviewStatus` 같은 자동 처리 표시는 사람의 승인과 다릅니다. `approved`라는 글자만 붙인 외부 JSON은 승인 증거로 인정되지 않습니다. 최신 연결 기록의 검수자·이유·확인·시각과 현재 노트가 일치해야 합니다.

## 3. 같은 노트로 A/B 청음하기

1. Unity **Play 모드**에서 러닝 게임을 실행합니다. Chart Lab으로 돌아오면 게임이 일시정지됩니다.
2. 행의 `이 구간 보기` 또는 `구간 시작`·`끝`으로 범위를 정하고, `원본·수정본 A/B 청음과 파형`을 펼칩니다.
3. `파형 읽기/새로고침`을 누릅니다. 상단은 원곡의 파형, 아래 표시선은 **주황: 원시 AI / 회색: 이전 보정 / 청록: 현재 / 빨강: 거절 노트**입니다. 파형을 클릭하면 노트 추가 시각만 선택됩니다. 노트가 자동 추가되지는 않습니다.
4. `A 원시 AI 시각 청음 (4박)`과 `B 현재 시각 청음 (4박)`을 번갈아 듣습니다. 화면에 나타나는 실제 비교 구간과 노트 수를 확인합니다. `청음 정지`로 중단할 수 있습니다.

A와 B는 **현재 시각이 선택 구간 `[시작, 끝)` 안에 있는 동일한 AI 노트 ID 집합**을 사용합니다. A는 그 노트들의 원시 시각, B는 현재 시각에 비교 클릭을 냅니다. 수동 추가 노트는 양쪽 모두에서 제외하고 수를 표시합니다. 원시 시각이 범위 밖으로 이동한 노트가 있으면 양쪽의 음원 구간을 같은 범위로 확장하므로, 한쪽 끝 노트만 조용히 빠지지 않습니다.

이 청음은 현재 남아 있는 노트의 시각 비교입니다. **선별에서 빠진 모든 AI 후보를 재생하는 기능은 아닙니다.** 음원 속도·음높이는 그대로이며, 4박 준비와 비교 클릭은 미리 만든 오디오 버퍼를 DSP 시간에 맞춰 재생합니다. 게임의 입력 판정·점수·HP에는 적용하지 않습니다.

파형은 원곡 PCM의 진폭을 요약한 그림입니다. 큰 봉우리가 곧 정답 박자이거나 타격음의 확정 위치인 것은 아닙니다. 파형은 어긋남을 찾는 단서로 쓰고, 청음과 실제 입력으로 판단하세요. PCM을 읽을 수 없는 음원 설정이면 파형을 표시할 수 없다는 안내가 나옵니다. 도구를 재생하거나 파형을 표시한 것만으로 청음 검수가 완료되지는 않습니다.

## 4. 실제 입력·수정·사람의 검수 기록

### 한 구절씩 플레이

- `반복`과 시작·끝 범위를 설정하고 `현재 채보 적용 (Game 뷰 4박)`을 누릅니다. 현재 문서의 기술 검사가 통과해야 적용됩니다. 게임은 일시정지 상태로 준비되므로 Game 뷰에서 재개합니다.
- `자동 입력`은 완주·표시·구간 연결 확인용입니다. 손으로 칠 수 있는 난이도를 입증하지 않습니다. 한 손 난이도를 볼 때는 자동 입력을 끄세요. 필요한 경우 `무적`으로 반복하되 사용 여부를 검수 이유나 테스트 기록에 남깁니다.
- 빠른 패턴 뒤 회복할 틈이 있는지, 쉼이 자연스러운지, 여러 동심원 중 다음 타이밍을 읽을 수 있는지, 15콤보 진입 뒤에도 원곡과 입력 감각이 유지되는지 확인합니다.

### 시각 편집

노트 행의 현재 시각을 바꾸거나 `추가 시각`·`노트 추가`·`삭제`를 사용합니다. `수정 이유`에 변경 근거를 남깁니다. 원시·이전 시각과 기존 검수 이력은 보존합니다. 승인했던 노트를 다시 편집하면 해당 승인은 `pending`으로 돌아가며, 이전 승인 기록은 역사로 남습니다. 수동 추가 노트는 `manual_edit` 출처로 남아 AI 생성으로 표시되지 않습니다.

### 검수 결정 기록

1. 확인한 행의 체크박스를 선택하고 `사람의 검수 기록`을 펼칩니다.
2. `검수자`, 구체적인 `검수 이유`, `결정`을 입력합니다. 예: “보통 / 휴대폰 가로 / 한 손 / 이 구절 3회 입력, 원시보다 현재 클릭이 킥에 맞음”. 하지 않은 청음이나 기기 검사를 적지 않습니다.
3. `approved`로 기록할 때는 **`직접 청음·입력과 현재 시각을 확인함`**을 직접 체크합니다. 확인 체크는 기록 후 해제됩니다.
4. `선택 N개에 검수 기록`을 누릅니다. 구절 전체를 확인한 경우에만 `구간 N개에 구절 검수 기록`을 사용합니다.

**선택 기록과 구절 기록의 범위가 다릅니다.** 선택 기록은 체크한 ID에 적용되며, 필터를 바꿔 숨겨진 선택도 남을 수 있습니다. 범위를 바꿀 때 `선택 해제`와 표시된 개수를 확인하세요. 구절 기록은 현재 필터·체크 여부와 관계없이 `[시작, 끝)`의 모든 현재 노트에 적용됩니다.

기록에는 검수자·이유·결정·UTC 기록 시각·당시 노트 시각과 출처가 남습니다. 기술 검사, A/B 재생, 자동 입력은 사람의 승인을 생성하지 않습니다. **모든 노트를 승인해도 `trainingEligible=false`를 유지**합니다. 학습 데이터 사용은 별도 명시 승인 절차이며, 이 테스트실에는 학습 승인 버튼이 없습니다.

## 5. 수정본·CSV와 팀 전달

| 버튼 | 결과 |
|---|---|
| `검증 후 수정본 저장` (`SaveVariant`) | 현재 기술 검사를 통과한 JSON을 `PlaytestExports/Runner/<난이도>-edited-<시각>.json`에 저장합니다. 기본 Resources 채보는 덮어쓰지 않습니다. |
| `검증 전 초안 저장` | 작업 중인 JSON을 `<난이도>-draft-<시각>.json`으로 보존합니다. 유효한 게임 채보·사람의 승인·배포 완료를 의미하지 않습니다. |
| `시각·검수 CSV` | `<난이도>-notes.csv`: 원시·이전·현재 시각, 이동 ms, 판정창, 출처, 검수 상태·검수자·이유를 내보냅니다. |
| `입력 로그 CSV` | `input-log.csv`: 실제 입력 이벤트와 타깃·오차·결과를 저장합니다. 이 파일만으로 무입력 누락을 셀 수는 없습니다. |
| `누락 포함 노트 결과 CSV` | `note-decisions.csv`: 모든 런타임 노트의 판정 결과를 저장합니다. 무입력 미스는 `omitted`, 입력 시각·오차는 공란입니다. 대기·건너뜀도 구분합니다. |

모드·난이도 변경이나 새 문서 불러오기 전에 저장하지 않은 편집은 초안으로 보존합니다. 그래도 팀에 보낼 파일은 명시적으로 `검증 후 수정본 저장`을 눌러 경로를 확인하세요. CSV는 같은 이름으로 다시 저장되므로, 기기·검수자·세션별로 복사하거나 이름을 바꿔 보관합니다. JSON 검수 기록이 원본이며 CSV는 비교·분석용입니다.

권장 전달 묶음은 수정본 JSON, 시각·검수 CSV, 실제 입력·노트 결과 CSV, 사용 기기·출력 장치·싱크 설정·자동 입력/무적 사용 여부입니다. 승인 노트가 포함된 수정본을 선별기에 전달하는 절차는 다음과 같습니다.

## 6. CLI: 임시 선별 → 검토 → 적용 → 되돌리기

아래 명령은 **Unity 프로젝트 루트**에서 실행합니다. Python과 NumPy가 필요합니다. 이 작업에는 Unity AI나 원본 Unity CLI가 필요하지 않습니다.

### 임시 결과 만들기

```sh
python3 Tools/Runner/prepare_charts.py
```

기본 결과는 `PlaytestExports/Runner/staging/<실행해시>/`에 생성되고 Assets는 바뀌지 않습니다. 이미 있는 폴더는 덮어쓰지 않습니다. 새 사본이 필요하면 `--output /절대경로/새폴더`를 지정합니다.

Chart Lab에서 저장한 검수본을 이어 쓰려면 다음처럼 전달합니다. 경로와 파일명은 실제 저장본으로 바꿉니다.

```sh
python3 Tools/Runner/prepare_charts.py \
  --review-chart "normal=PlaytestExports/Runner/normal-edited-검수본.json" \
  --output "PlaytestExports/Runner/staging/team-review-new"
```

`--review-chart PRESET=PATH`는 `easy`·`normal`·`hard`에 대해 반복할 수 있습니다. 미지정 난이도는 현재 Resources 채보를 사용합니다. 같은 난이도를 두 번 지정하거나 곡·난이도가 다른 문서를 전달하면 중단합니다.

이 옵션은 **검수 기록을 선별 입력으로 전달**합니다. 저장본을 그대로 배포 폴더로 복사하는 명령이 아닙니다. 증거가 유효한 현재 승인은 고정하고, 거절한 후보는 제외합니다. 대기 노트는 규칙에 따라 다시 선별될 수 있으므로 출력본을 확인해야 합니다. 난이도 사이에 공유하는 노트의 승인 시각이나 결정이 충돌하면 조용히 덮어쓰지 않고 중단합니다. 해당 구절을 비교해 팀이 먼저 정리하세요.

### 임시 결과 검토

출력 폴더에는 난이도별 JSON·CSV, 다음 보고서와 스냅샷이 있습니다.

- `validation.json`: 기술 검사와 선별 요약.
- `reviewQueue.json`: 사람의 A/B·청음·한 손 검수가 남은 항목.
- `candidateDecisions.json`, `excludedCandidates.json`: 후보 선택·제외 근거.
- `reviewWarnings.json`: 오래된 승인 등 검수 입력 경고.
- `review-input-<난이도>.json`: 사용한 검수 입력의 정확한 사본.
- `rules.json`, `stage.json`, `manifest.json`: 사용 설정·스테이지와 재현/파일 검증 정보.

해당 JSON을 Chart Lab으로 불러와 현재 기술 검사와 구절 검수를 진행합니다. 수정이 생기면 새 수정본을 저장한 뒤 `--review-chart`로 **새 staging을 생성**합니다. staging 안의 파일을 직접 고치면 해시가 달라져 적용되지 않습니다.

`--raw-comparison`은 원시 시각 비교 자료를 만드는 진단 옵션이며 적용할 수 없습니다. 현재 채보의 시각 비교에는 Chart Lab A/B를 사용하세요.

### 로컬 게임 채보에 적용

```sh
python3 Tools/Runner/prepare_charts.py --apply "/절대경로/staging폴더"
```

세 난이도를 다시 검사하고, 변경 전 사본을 `PlaytestExports/Runner/chart-backups/<실행해시>/`에 만든 뒤 `Assets/Afterecho/Resources/Afterecho/RunnerCharts/`의 채보 JSON을 교체합니다. 실제 경로는 명령 출력의 `backup`을 확인해 보관합니다. 적용 전후에 다른 사람이 같은 로컬 채보를 편집하지 않도록 합니다.

선별 이후 코드·설정·음원·스테이지·기본 채보가 바뀌었거나 staging 파일이 수정되면 적용을 거절합니다. 검사를 우회하지 말고 변경 내용을 보존한 뒤 새 staging을 만드세요. 적용 후에는 Unity에서 기본 채보를 다시 읽고 게임 구동을 확인합니다.

**`--apply`는 로컬 JSON 적용입니다. Git 커밋·푸시, WebGL 빌드, 공개 웹 업로드를 수행하지 않습니다.** 팀이 보관·배포할 버전을 확인한 다음 각각의 배포 작업을 진행합니다.

### 적용 전 상태로 되돌리기

```sh
python3 Tools/Runner/prepare_charts.py --rollback "/절대경로/chart-backups/실행해시"
```

백업 해시와 현재 파일을 확인한 뒤 복원합니다. 적용 이후 별도 편집이 있으면 그 편집을 지우지 않도록 거절하므로, 먼저 수정본을 보존합니다. 세 파일 교체 중 프로세스가 중단된 경우에도 정확한 적용 전·후 파일이 섞인 상태는 복구 대상으로 인식합니다. 백업과 그 `manifest.json`을 함께 보관하세요.

## 7. 검수 완료 전에 남겨야 할 확인

- 현재 문서의 기술 검사와 기본 채보 회귀검사를 구분해 기록했습니다.
- 큰 시각 이동뿐 아니라 구절 경계·쉼·빠른 패턴을 원곡과 비교했습니다.
- 실제 입력에서 다음 원을 읽을 수 있고, 미스·연타·질주 중에도 타이밍을 유지하는지 확인했습니다.
- 노트 시각·판정 결과·CSV가 같은 수정본을 기준으로 하는지 확인했습니다.
- 승인에는 실제 검수자·이유·현재 시각의 확인 기록이 있고, 재편집한 승인은 다시 확인했습니다.
- 실제 휴대폰의 오디오 지연, 유선·무선 출력 차이와 한 손 난이도는 해당 기기에서 검수했습니다. 아직 하지 않았다면 **실기기 검수 대기**로 남깁니다. Editor 자동 완주나 PC 청음으로 대신 완료 처리하지 않습니다.
