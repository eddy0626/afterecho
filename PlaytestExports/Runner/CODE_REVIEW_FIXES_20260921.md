## 로컬 CLI와 키체인 요청

초기 `Tools/unity-local`은 원본 CLI를 비대화형으로 호출하도록 제한했다. 그러나 사용자가 키체인 창이 계속 나타나는 화면을 제공했으므로, 초기 방식으로 인증창이 방지됐다는 앞선 관찰은 철회한다.

재발 후에는 원본 CLI 실행을 제거하고, 설치된 Unity Pipeline의 문서화된 로컬 HTTP 연결을 사용하는 Python 도구로 교체했다. 현재 프로젝트의 연결 파일과 기존 세션 인증으로 `127.0.0.1`에만 연결하며, 계정·키체인 API를 호출하거나 원본 CLI로 자동 재시도하지 않는다. 기존 게임의 검사 결과와 WebGL 빌드는 이 도구 변경으로 달라지지 않는다.

macOS의 키체인 보호나 저장된 비밀번호는 변경하지 않았다. 이미 떠 있는 보안 창은 화면 제어 도구가 조작을 거절하여 사용자가 '거부'로 닫아야 한다. 계정 로그인 또는 다른 Unity/Hub 작업에서 발생하는 인증 요청까지 전역 차단하는 설정은 아니다. 상세 사용법은 `Tools/LOCAL_EDITOR_WORKFLOW.md`를 참고한다.

교체 후 실제 연결 검증: `status`가 `ready`, 필터를 사용한 명령 목록 조회 정상, `eval`의 `1+1` 결과가 2이며 `Stage01_RunnerCircle` 씬·Play 중지·컴파일 중 아님을 확인했다. `build_status`를 기존 `data.result` 형식으로 읽어 마지막 빌드 `build_98b79075b674 / Succeeded`를 확인했다. 이 확인 시 원본 `.unity/bin/unity` 프로세스는 0개였다. 이는 새 연결 경로 검증이며, 기존 macOS 보안 창이 닫혔다는 증거는 아니다.

로컬 연결 도구 회귀검사 `python3 Tools/test_unity_local.py`: 15개 통과. 프로젝트/파일 소유자/권한/심볼릭 링크/특수 파일/프로세스/포트/토큰 검증, 인증 실패 및 리다이렉트 시 종료, 토큰 출력 제거, 명령 인자와 결과 호환, 작업 취소 성공 처리, 원본 CLI 미호출을 합성 데이터와 모의 HTTP로 검사했다. 실제 저장된 인증정보는 변경하지 않았다.
