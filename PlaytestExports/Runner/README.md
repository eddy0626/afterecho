# 잔향 AFTERECHO — 중앙 원·4면 러닝 팀 테스트

[브라우저에서 바로 플레이](https://play.unity.com/en/games/c81e0f9d-00d9-4904-87ee-8844fdfe0af6/afterecho-runner)

새 씬: `Assets/Afterecho/Scenes/Stage01_RunnerCircle.unity`
작업 브랜치: `feature/runner-circle`
Unity: 6000.6.0f1 / Feel 6.1 / DOTween 1.3.030

중앙 원이 기준 원에 겹치는 순간 화면 어디든 한 번 누릅니다. 일반 키보드 키도 사용할 수 있습니다. Esc와 우측 상단 버튼은 일시정지입니다. 키를 계속 누르고 있어도 자동 입력되지 않습니다. 첫 화면에서 입문·보통·도전을 선택하고, 안전한 연습 또는 4박 후 실전 시작을 선택합니다. 실전 음악과 채보는 항상 0초부터 시작합니다.

HP는 100으로 시작하며 성공 +1, 미스 −10, 헛입력 −3입니다. 쉼에서 가만히 있는 것은 감점하지 않습니다. 15콤보부터 러너 속도가 2.4배가 되며 콤보가 끊기면 해제됩니다. 음악 속도와 노트 시각은 고정됩니다. 미스 시 넘어졌다 일어나는 동안에도 입력할 수 있습니다. 원곡 136.36초 종료까지 생존하면 완주입니다.

## 실행

- Unity Hub에서 프로젝트를 열고 새 씬을 연 뒤 Play를 누릅니다.
- WebGL 팀 ZIP을 풀고 동봉한 `실행.command` 또는 `실행.bat`을 실행한 다음 `http://127.0.0.1:8777`을 엽니다. Python 3.9 이상이 필요합니다. HTML 파일을 직접 더블클릭하는 방식은 지원하지 않습니다.
- 이미 Python 3가 설치된 개발 PC에서는 프로젝트 루트에서 `python3 Tools/Runner/serve.py`로 동일하게 실행합니다.
- WebGL 테스트 주소 뒤 `?autoplay=1&difficulty=hard`를 붙이면 자동 입력을 켤 수 있습니다. `?invincible=1`은 무적 테스트입니다. 화면 모서리에 테스트 모드가 표시됩니다. 시작은 반드시 버튼으로 합니다.
- 음량, 싱크, 움직임 줄이기는 첫 화면에서 조절하며 기기별로 저장됩니다.

## 팀 조정

로컬 Unity 작업은 프로젝트의 `Tools/unity-local`을 사용합니다. 원본 Unity CLI 실행 파일을 호출하지 않고 현재 열린 Editor에 인증된 로컬 연결을 사용합니다. 자세한 사용법은 `Tools/LOCAL_EDITOR_WORKFLOW.md`에 있습니다.

`Afterecho → Chart Lab`에서 모드를 `runner`로 선택합니다. 난이도별 확정 노트 ID·초 단위 시각·판정창·검수 상태를 확인하고 추가·삭제·시각 수정을 할 수 있습니다. 수정 이유를 입력한 뒤 JSON/CSV를 저장합니다. Play 상태에서는 구간 반복, 자동 입력, 무적, 입력 로그 저장을 사용할 수 있습니다.

`현재 채보 검증`은 화면에서 편집 중인 문서를 검사하고, `기본 채보 회귀검사`는 프로젝트에 저장된 기본 3종 채보를 검사합니다. 구간 반복은 현재 적용한 수정본을 계속 사용합니다.

`러닝 규칙 조절` 버튼으로 `RunnerRules.asset`을 선택합니다. HP·피해·회복·질주 콤보·배속·한 바퀴 시간·미리보기·넘어짐 시간을 조정합니다. 시작 HP를 바꾼 뒤에는 재시작합니다. 기본 채보 미리보기는 1.2초이며 화면에서 임의로 노트를 숨기지 않습니다. `legacy combat` 모드와 기존 복도 씬은 비교를 위해 보존했습니다.

## 채보 출처와 검수

기존 BeatLearning 공개 모델 초안을 복사하고, 원곡의 5ms 단위 타격 강도와 후보 시각을 비교해 밀집 노트만 줄였습니다. 이번 개편에서 모델 학습이나 새 AI 채보 생성을 하지 않았습니다. 기존 모델 버전·해시·노트 ID·원 시각은 JSON에 유지됩니다. `runnerEdits`에 삭제 사유와 수정 시간을 기록합니다.

| 난이도 | 노트 수 | 최소 간격 | 최대 판정창 | 1.2초 최대 표시 수 |
|---|---:|---:|---:|---:|
| 입문 | 239 | 300ms | ±100ms | 4 |
| 보통 | 257 | 220ms | ±80ms | 4 |
| 도전 | 289 | 169.614ms | ±60ms | 5 |

실제 판정창은 인접 간격의 40% 이하입니다. `*-original.json`은 이전 채보, `*-notes.csv`는 개편 채보 표, `*-transients.json`은 분석 근거입니다. 원곡 말미의 짧은 무노트 구간도 음악은 끝까지 재생됩니다.

자동 검사는 청음 검수를 대신하지 않습니다. 음악적 자연스러움·한 손 난이도·실제 휴대폰 오디오 지연은 팀 검수 대기이며, 학습 데이터 사용 가능 표시는 꺼져 있습니다.

## 아트와 효과음

GPT에서 독자적인 실루엣 캐릭터와 화면 스타일 시안을 제작했습니다. Grok에서 같은 캐릭터의 달리기·질주·넘어짐 키포즈를 만들고, Gameaify Sprite Studio에서 보간과 투명 배경 처리를 했습니다. 형태가 달라진 피격 프리셋은 최종 사용에서 제외했습니다. 일어나기는 검수한 넘어짐 동작을 역순으로 재생하며, 전환까지 합쳐 기본 0.35초입니다.

프레임 크기는 256px이며 Unity에서 발 접점을 정렬합니다. 기본 달리기와 질주는 별도 프레임 목록·재생 속도·전경 자세를 사용합니다. Feel은 중앙 원, HP, 질주 진입, 넘어짐 반응을 담당하고 DOTween은 헛입력의 짧은 비틀거림을 담당합니다. 히트스톱이나 음악 재생 속도 변경은 없습니다.

ElevenLabs에서 GOOD·PERFECT·FALL·BOOST·CLEAR 효과음을 제작했습니다. 시작 무음과 잔향을 줄이고 모노 48kHz PCM으로 가져왔습니다. 원본과 가공 내역은 `audio-provenance.json`, `ArtProduction/Runner/AudioSources`에 있습니다.

Gameaify Editor에서 생성한 메뉴 프레임·버튼·HP 테두리·질주 배지를 추가했습니다. 9-slice 스프라이트로 크기에 대응하고 텍스트·실제 HP·판정 원은 Unity UI로 유지합니다. 제작 출처와 적용 기록은 `UI_GAMEAIFY_20260921.md`에 있습니다.

## 빌드와 보존

별도 프로필 `Afterecho_RunnerCircle_Web_Test`는 개편 씬 하나만 포함합니다. 기존 `Afterecho_Web_Team_0913 - Desktop - Release`의 작업 전 로컬 수정과 기존 복도 씬은 보존했습니다. 원본 씬·프로필의 외부 공개 빌드는 그대로 두고, 새 러닝 버전을 별도 Unity Play 페이지에 게시합니다.

`Tools/Runner/prepare_charts.py`는 NumPy를 사용하며 기존 후보 채보에서 수정본을 재현합니다. `finalize_art.cs`는 연결된 Unity Editor의 CLI에서 실행하는 에디터 처리 파일입니다. 일반 플레이에는 생성 모델이나 별도 서버 API가 필요하지 않습니다.

`prepare_audio.py`는 동봉한 ElevenLabs 원본 WAV에서 효과음을 다시 가공하며 FFmpeg가 필요합니다. 일반 플레이에는 Python 패키지나 FFmpeg가 필요하지 않습니다. WebGL 로컬 실행 서버만 Python 표준 라이브러리를 사용합니다.

오디오 진단이 필요하면 테스트 URL에 `debug=1`을 추가합니다. 브라우저 콘솔의 `RUNNER_CLOCK`에는 실제 재생 위치와 게임 시간, 입력 결과가 기록됩니다. WebGL 러닝 모드는 실제 오디오 소스 위치를 판정 시계로 사용합니다. 첫 음악 채널은 무음 준비 후 정지하고, 4박 카운트와 0초 실전을 새로 예약합니다. `RunnerAudioClock.jslib`가 Unity 6000.6.0f1의 실제 Web Audio 음악 노드 위치를 읽고 배속 1을 유지합니다. 노래의 속도나 음높이를 게임 규칙으로 변경하지 않습니다. Unity 버전을 올릴 때는 이 연결부와 재개·완주를 다시 검증해야 합니다.

## 현재 알려진 제한

실제 PC 창에서는 첫 화면이 정상이다. Chrome의 모바일 화면 크기 에뮬레이션에서 새로고침 직후 화면이 작게 나올 수 있으며, 창 크기 변경 또는 가로·세로 전환으로 정상화된다. 실제 휴대폰의 첫 로딩·회전·오디오 지연은 팀 검수 전이다.

첫 재생은 브라우저 음악 채널을 무음으로 준비한 뒤 4박을 예약한다. 오디오가 중단되면 체력 피해 없이 멈추며 버튼으로 다시 이어갈 수 있다.
