# 중앙 원 · 4면 러닝 검증 기록

## 자동 기술 검증

- 새 러닝 핵심 101개 검사 통과: 판정창 안/밖 경계, 밀집도, 최대 4타 후 회복 간격, HP 회복/피해/상한, 미스 단일 처리, 질주 조건, 쉼, 20Hz 연타 실패, 중복 접점, 게임오버 단일 처리, 종료 시각.
- 기존 전투 모드 회귀 검사 111개 통과.
- 실제 Editor DSP 재생으로 세 난이도 원곡 전체 자동 완주: 입문 239 / 보통 257 / 도전 289 성공, 미스·헛입력 0, HP 100, 음악 배속 1.0, 136.36초 완주.
- 실제 Editor 무입력 실행: 모든 난이도 10회 누락 시 HP 0. 이 검사는 외부 키 입력이 끼어들지 않도록 입력 액션만 일시 비활성화하고 끝난 뒤 복원했다.
- 실제 Input System 키 이벤트로 DSP 노트 성공, 키 유지/반복 1회만 수신, 일시정지 시 음악·채보·러너 정지, 4박 재개, 오디오 중단 자동 정지, 재시작 0초 확인.
- 넘어짐 중 다음 노트 성공, 연속 미스 시 넘어짐 종료 시각이 늘어나지 않는 것을 확인.
- CSV 시각과 판정창은 표시/판정에 사용하는 동일 채보에서 내보낸다.

원시 결과는 `core-tests.txt`, `live-*.json`, `live-input-checks.txt`, `live-fall-checks.txt`, `live-contact-checks.txt`에 있다.

## 아트 검수

원본 캐릭터와 다른 형태로 변한 Gameaify 피격 프리셋은 제외했다. 최종 기본 달리기 16프레임, 질주 63프레임, 넘어짐 12프레임, 일어나기 12프레임을 연결했다. 일어나기는 넘어짐 역재생이다. Unity Editor에서 프레임별 불투명 픽셀의 최하단을 측정해 발 접점을 맞췄다. 네 면에서 루트 방향만 회전하며 UI는 고정된다.

## 팀 실기기 검수 대기

- 실제 휴대폰별 오디오 출력 지연과 싱크 보정값.
- 입문/보통/도전 채보의 음악적 자연스러움과 한 손 난이도.
- 휴대폰에서 효과음·원곡의 최종 청감 균형.
- 장시간 플레이에서 원 크기, 미리보기 1.2초, 질주 잔상의 편안함.

자동 검증 통과를 팀 청음 검수 완료로 표시하지 않는다. `teamReview`와 학습 데이터 적격 여부는 대기/false로 유지한다.

## 빌드

WebGL 테스트 빌드 성공, 컴파일 오류 0. 전체 빌드 크기는 약 32.8MB이다. 설치된 패키지의 셰이더 변형, 선택적 Feel 연동 리소스, DOTween 구형 importer metadata 등에 관한 경고가 남아 있으며 `build-warnings.json`에 원문을 보존했다. 개편 씬은 해당 선택적 리소스를 사용하지 않는다.

## WebGL 실제 브라우저 검증

Chrome 터치 에뮬레이션 844×390에서 도전 채보를 자동 입력으로 실행했다. 28.684초에 Esc 일시정지, 98.181초에 세로 전환 자동 정지 후 각각 4박 재개했다. 실제 Web Audio 노드 재생 속도는 계속 1.0이며, 재개 후 실시간 10초에 음악도 약 10초 진행했다. 136.367초에 289노트 / 미스 0 / 헛입력 0 / HP 100 / 정확도 100% / 점수 110,300으로 완주했다. 결과 화면을 직접 확인했다. 이 검사는 자동 입력과 동기화 검증이며 사람이 곡에 맞춰 잘 칠 수 있다는 난이도 검증은 아니다.

Unity의 WebGL 오디오 시간/샘플레이트 차이를 피하기 위해 실제 Web Audio 음악 노드의 위치를 사용한다. `RunnerAudioClock.jslib`는 Unity 6000.6.0f1에 맞춰 작성됐으므로 Editor 업그레이드 후 재검증 대상이다.

브라우저에서 직접 J 키로 노트 성공(미스 0 / 헛입력 0 / HP 100), 터치 노트 성공, 잘못된 타이밍의 감점, 무입력 10미스로 HP 0 결과 화면을 확인했다. 입력 원시 결과는 `web-direct-input.json`에 기록했다.

## 남은 화면 호환성 확인

실제 PC 창 크기에서는 첫 로딩부터 전체 화면 배치가 정상이다. Chrome의 화면 크기 에뮬레이션에서는 새로고침 직후 게임이 좌상단에 작게 렌더되는 현상이 남아 있다. 창 크기를 한 번 바꾸면 가로 배치와 입력 위치가 정상화된다. 844×390 가로 상태의 원·HP·버튼과 390×844 세로 전환 자동 정지는 확인했으나, 에뮬레이션 초기화 현상을 실기기 정상으로 간주하지 않는다. 실제 휴대폰 첫 로딩과 회전은 팀 확인 대상이다.

최종 전달 빌드 `build_f711ade53221`에서도 다시 전체 원곡을 실행했다. 첫 음악 준비 후 재시도 없이 시작했고 31.767초에 세로 전환으로 정지한 뒤 4박 재개했다. 136.366초에 289 성공 / 미스 0 / 헛입력 0 / HP 100 / 110,300점으로 완주했으며 재생 속도는 1.0이었다. `web-final-completion.json`에 기록했다.
